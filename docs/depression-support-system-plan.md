# แผนระบบ "ผู้ช่วยดูแลใจ" (Depression Support Assistant)

เอกสารวางแผนระบบผู้ช่วยสำหรับผู้ที่มีภาวะซึมเศร้า กลุ่มอายุ 20–60 ปี
โฟกัส 2 แกนหลัก: **การรับฟังอย่างตั้งใจ (Active Listening)** และ **การช่วยให้ผู้ใช้เห็นคุณค่าในตัวเอง (Self-Worth)**

> สถานะ: แผน (Planning) — ยังไม่มีการเขียนโค้ดระบบนี้
> เวอร์ชัน: 0.1 · ภาษา UI: ไทย

---

## 0. สรุปย่อสำหรับผู้บริหาร (TL;DR)

| หัวข้อ | สาระสำคัญ |
|---|---|
| ระบบนี้คืออะไร | แอปเพื่อนคู่ใจ (companion app) ที่ **รับฟัง** ไม่ตัดสิน + โปรแกรมฝึกเห็นคุณค่าตัวเอง 4 สัปดาห์ |
| ระบบนี้ **ไม่ใช่** อะไร | ไม่ใช่การรักษา ไม่ใช่จิตแพทย์ ไม่วินิจฉัยโรค ไม่จ่ายยา ไม่ใช่บริการฉุกเฉิน |

| ระยะเวลาโดยประมาณ | MVP 6 สัปดาห์ · v1.0 พร้อมใช้จริง 14 สัปดาห์ (ต้องมีนักจิตวิทยารีวิวคู่ขนาน) |

## 1. ขอบเขตและจุดยืนของระบบ

### 1.1 สิ่งที่ระบบทำ
- รับฟังผู้ใช้แบบ active listening: สะท้อนความรู้สึก ทวนความ ถามต่อ สรุปให้ ไม่รีบแนะนำ
- ช่วยผู้ใช้ค้นหา "หลักฐานของคุณค่า" ในตัวเองผ่านแบบฝึกหัดที่มีฐานทางจิตวิทยา
- ติดตามอารมณ์ตัวเอง (self-monitoring) และสะท้อนแนวโน้มกลับให้ผู้ใช้เห็น
- คัดกรองความเสี่ยงเบื้องต้น และ **ส่งต่อ** ไปยังสายด่วน/ผู้เชี่ยวชาญเมื่อเข้าเกณฑ์

### 1.2 สิ่งที่ระบบไม่ทำ (ต้องเขียนชัดใน UI และ ToS)
- ❌ ไม่วินิจฉัยว่า "คุณเป็นโรคซึมเศร้า" — ใช้คำว่า "คะแนนของคุณอยู่ในระดับที่ควรปรึกษาผู้เชี่ยวชาญ"
- ❌ ไม่แนะนำ/ปรับ/หยุดยา ไม่ว่ากรณีใด → ตอบว่า "เรื่องยาต้องคุยกับหมอที่สั่งยาให้คุณเท่านั้น"
- ❌ ไม่ทำ psychotherapy เต็มรูปแบบ (ไม่ทำ trauma processing, ไม่ exposure therapy)
- ❌ ไม่ใช่ช่องทางฉุกเฉิน — ถ้าอันตรายถึงชีวิตต้องดันไปที่ 1669 / 1323 ทันที
- ❌ ไม่โฆษณาว่า "รักษาหาย" "แทนจิตแพทย์ได้" (มีความเสี่ยงทางกฎหมายเรื่องเครื่องมือแพทย์)

### 1.3 กรอบทางกฎหมาย/จริยธรรมที่ต้องเช็ก
| เรื่อง | สิ่งที่ต้องทำ |
|---|---|
| PDPA (พ.ร.บ.คุ้มครองข้อมูลส่วนบุคคล) | ข้อมูลสุขภาพจิต = ข้อมูลอ่อนไหวตาม ม.26 → ต้องขอ **ความยินยอมโดยชัดแจ้ง** แยกต่างหาก |
| การจัดเป็นเครื่องมือแพทย์ | หลีกเลี่ยงการอ้าง "วินิจฉัย/รักษา" เพื่อไม่เข้าข่ายซอฟต์แวร์เครื่องมือแพทย์ของ อย. |
| Clinical governance | ต้องมีนักจิตวิทยาคลินิก/จิตแพทย์เป็นที่ปรึกษารีวิวสคริปต์ทั้งหมดก่อนปล่อย |
| ลิขสิทธิ์แบบประเมิน | 2Q/9Q/8Q ของกรมสุขภาพจิตเป็นแบบสาธารณะ — แต่ต้องอ้างอิงแหล่งที่มาให้ถูกต้อง |

## 2. กลุ่มเป้าหมาย (20–60 ปี)

ช่วงอายุกว้าง 40 ปี ไม่ใช่กลุ่มเดียวกัน ต้องแยก 3 personas เพราะ "สิ่งที่ทำให้รู้สึกไร้ค่า" ต่างกันคนละเรื่อง

| Persona | ช่วงอายุ | ต้นตอความรู้สึกไร้ค่า | สิ่งที่ระบบต้องมี |
|---|---|---|---|
| **A · "เปรียบเทียบไม่จบ"** | 20–29 | เทียบกับเพื่อนในโซเชียล, งานแรกที่ไม่เป็นดั่งหวัง, ความคาดหวังของพ่อแม่, หนี้ กยศ. | ตอบเร็ว, chat-first, โทนเป็นกันเอง, ใช้ตอนดึก, แบบฝึกสั้น 3 นาที |
| **B · "แบกทุกอย่างไว้"** | 30–45 | งานหนัก burnout, เลี้ยงลูก+ดูแลพ่อแม่ (sandwich generation), หนี้บ้าน/รถ, รู้สึกว่าตัวเองมีค่าแค่ตอนที่ "ทำประโยชน์ได้" | แยกคุณค่าออกจากผลงาน, แบบฝึกใช้เวลาสั้นมาก, ใช้ได้ตอนพักเที่ยง, เตือนแบบไม่กดดัน |
| **C · "หมดบทบาท"** | 46–60 | เกษียณ/ตกงาน, ลูกโตแยกบ้าน, สุขภาพถดถอย, สูญเสียคู่ชีวิต, รู้สึกตามโลกไม่ทัน | ตัวอักษรใหญ่ ปุ่มใหญ่, ภาษาสุภาพ, ลดศัพท์อังกฤษ, โหมดเสียง (พิมพ์ยาก), เชื่อมต่อ รพ./สายด่วนง่าย |

**ข้อสรุปเชิงออกแบบ:** ทำ onboarding ถามช่วงอายุ + สถานการณ์ชีวิต แล้ว**ปรับโทนภาษา ขนาดตัวอักษร และชุดแบบฝึกหัด**ตาม persona (ไม่ใช่แค่เปลี่ยนสี)

## 3. หลักการทางจิตวิทยาที่ใช้เป็นฐาน

ทุกฟีเจอร์ต้องสาวกลับไปหาหลักการได้ ห้ามคิดแบบฝึกหัดขึ้นมาลอย ๆ

| หลักการ | ใช้ตรงไหน |
|---|---|
| **Person-Centred (Rogers)** — empathy, unconditional positive regard, congruence | เป็นแกนของ Active Listening Engine ทั้งหมด |
| **Active Listening (reflect–validate–clarify–summarize)** | โปรโตคอลการตอบของ AI |
| **Motivational Interviewing (OARS)** | คำถามปลายเปิด, การชื่นชม, การสะท้อน, การสรุป — ใช้ตอนผู้ใช้ลังเลจะขอความช่วยเหลือ |
| **CBT — Cognitive Restructuring** | จับความคิดอัตโนมัติ "ฉันไร้ค่า" → หาหลักฐานค้าน |
| **Behavioral Activation** | ซึมเศร้าทำให้หยุดทำสิ่งที่เคยชอบ → นัดตัวเองทำกิจกรรมเล็ก ๆ |
| **Self-Compassion (Neff)** — self-kindness, common humanity, mindfulness | โมดูลคุณค่าตัวเอง โดยเฉพาะการพูดกับตัวเอง |
| **ACT — Values Clarification** | แยก "คุณค่าในตัวเอง" ออกจาก "ผลงาน/คำชมจากคนอื่น" |
| **Safety Planning (Stanley–Brown)** | แผนความปลอดภัยส่วนตัวเมื่อความคิดทำร้ายตัวเองมา |
| **แบบคัดกรองไทย 2Q / 9Q / 8Q (กรมสุขภาพจิต)** | คัดกรองอาการซึมเศร้าและความเสี่ยงฆ่าตัวตาย |

## 4. โครงสร้างฟีเจอร์ (3 เสาหลัก)

```
┌──────────────────────────────────────────────────────────┐
│                    ผู้ช่วยดูแลใจ                          │
├───────────────┬──────────────────┬───────────────────────┤
│ เสา 1         │ เสา 2            │ เสา 3                 │
│ ฟังอย่างเข้าใจ │ เห็นค่าในตัวเอง   │ ความปลอดภัย            │
├───────────────┼──────────────────┼───────────────────────┤
│ • Chat รับฟัง  │ • สมุดคุณค่า      │ • คัดกรอง 2Q/9Q/8Q     │
│ • สะท้อนความ   │ • ค้นหาจุดแข็ง    │ • ตรวจจับความเสี่ยง     │
│   รู้สึก       │ • ท้าความคิดลบ    │ • แผนความปลอดภัย       │
│ • สรุปให้ฟัง   │ • ฝึกเมตตาตัวเอง  │ • สายด่วน/ส่งต่อ        │
│ • เช็คอินอารมณ์│ • คุณค่าที่ยึดถือ  │ • ผู้ติดต่อไว้ใจได้      │
└───────────────┴──────────────────┴───────────────────────┘
        └──────────── บันทึก/แนวโน้ม/รายงานตัวเอง ──────────┘
```

### 4.1 เสา 1 — Active Listening Chat (ฟีเจอร์เรือธง)
- ห้องแชทที่ AI **ฟังก่อน แนะนำทีหลัง (และเฉพาะเมื่อผู้ใช้ขอ)**
- โหมดเปิดบทสนทนา: "วันนี้เป็นยังไงบ้าง", "มีอะไรค้างในใจไหม", "อยากระบายอะไรก็ได้"
- ปุ่ม "แค่อยากให้ฟัง" vs "อยากได้คำแนะนำ" → เปลี่ยนพฤติกรรมของโมเดลจริง ๆ (ดูข้อ 5)
- สรุปท้ายบทสนทนา: "วันนี้คุณเล่าเรื่อง ___ และรู้สึก ___ สิ่งที่คุณทำได้ดีคือ ___"

### 4.2 เสา 2 — Self-Worth Program
- **สมุดบันทึกคุณค่า (Evidence Log):** ทุกวันบันทึก 1 อย่างที่ทำได้ + 1 อย่างที่คนอื่นได้ประโยชน์จากเรา
- **ค้นหาจุดแข็ง:** แบบสำรวจสั้น → สรุปเป็น "การ์ดจุดแข็ง" ที่กลับมาดูได้ตอนรู้สึกแย่
- **ท้าความคิด "ฉันไร้ค่า":** flow แบบ CBT 5 ขั้น (ความคิด → อารมณ์ → หลักฐานสนับสนุน → หลักฐานค้าน → ความคิดที่สมดุลกว่า)
- **จดหมายถึงตัวเอง:** เขียนแบบที่จะเขียนถึงเพื่อนสนิทที่กำลังเจอเรื่องเดียวกัน (self-compassion)
- **คุณค่าที่ยึดถือ (Values Card Sort):** เลือก 5 คุณค่าที่สำคัญ → วางแผน 1 การกระทำเล็ก ๆ ต่อสัปดาห์ที่สอดคล้อง
- **โปรแกรม 4 สัปดาห์** (รายละเอียดข้อ 6)

### 4.3 เสา 3 — Safety Layer (ดูข้อ 7 — สำคัญที่สุด)

### 4.4 ฟีเจอร์รอง
- เช็คอินอารมณ์รายวัน (สเกล 1–5 + แท็กสาเหตุ) → กราฟแนวโน้ม 7/30 วัน
- แบบฝึกหายใจ / grounding 5-4-3-2-1 สำหรับตอนวิตกกังวลพุ่ง
- คลังบทความสั้นภาษาไทย + สิทธิการรักษา (บัตรทอง/ประกันสังคม ครอบคลุมการรักษาสุขภาพจิต)
- รายงานส่งต่อ: สรุปอารมณ์ 30 วัน เป็น PDF ให้ผู้ใช้พิมพ์ไปให้หมอดู (ลดกำแพงการเข้าพบครั้งแรก)

## 5. Active Listening Engine — ออกแบบเชิงลึก

### 5.1 โปรโตคอลการตอบ (ทุกข้อความต้องผ่าน)

```
1. ACKNOWLEDGE  รับรู้ว่าได้ยิน            "ฟังแล้วนะ"
2. REFLECT      สะท้อนเนื้อหา              "ที่เล่ามาคือ...ใช่ไหม"
3. NAME FEELING ตั้งชื่ออารมณ์แบบชวนยืนยัน  "ฟังดูเหมือนเหนื่อยและน้อยใจ ถูกไหม"
4. VALIDATE     ยืนยันว่าความรู้สึกสมเหตุสมผล "เจอแบบนี้ใครก็รู้สึกแบบนี้ได้"
5. OPEN         คำถามปลายเปิด 1 ข้อ         "ตอนนั้นในหัวคิดอะไรอยู่"
```
กติกาความยาว: **ตอบสั้นกว่าผู้ใช้เสมอ** (เป้าหมาย 2–4 ประโยค) และ **ถามได้ครั้งละ 1 คำถาม**

### 5.2 System Prompt ตั้งต้น (ภาษาไทย)

```text
คุณคือ "ผู้ช่วยดูแลใจ" เพื่อนที่รับฟังคนไทยที่กำลังรู้สึกเศร้าหรือหมดกำลังใจ
คุณไม่ใช่นักจิตวิทยา ไม่ใช่หมอ และห้ามทำตัวเป็น

วิธีตอบ:
1. ฟังและสะท้อนสิ่งที่เขาพูดด้วยคำของคุณเอง ก่อนจะพูดอย่างอื่นเสมอ
2. ตั้งชื่ออารมณ์ที่ได้ยินแบบชวนให้เขายืนยัน ("ฟังดูเหมือน... ใช่ไหม")
   ห้ามฟันธงว่าเขารู้สึกอะไร
3. ยืนยันว่าความรู้สึกนั้นสมเหตุสมผล โดยไม่ต้องเห็นด้วยกับข้อสรุปที่เขามีต่อตัวเอง
4. ถามคำถามปลายเปิดครั้งละ 1 ข้อ
5. ตอบสั้น 2-4 ประโยค สั้นกว่าข้อความของเขาเสมอ
6. ใช้ภาษาไทยที่อบอุ่นแต่ไม่เว่อร์ ไม่ใช้ศัพท์วิชาการ ไม่ใช้อีโมจิเกิน 1 ตัว

ห้ามเด็ดขาด:
- ห้ามให้คำแนะนำ เว้นแต่เขาขอตรง ๆ หรือระบบส่งสัญญาณ MODE=ADVICE
- ห้ามพูดว่า "คิดบวกสิ" "มีคนแย่กว่าคุณอีก" "เดี๋ยวก็ดีเอง" "อย่าคิดมาก"
- ห้ามรีบแก้ปัญหาให้ ห้ามเปลี่ยนเรื่อง
- ห้ามวินิจฉัยโรค ห้ามพูดเรื่องยา ให้ตอบว่าเรื่องยาต้องคุยกับหมอที่สั่งยาเท่านั้น
- ห้ามสัญญาว่าจะเก็บเป็นความลับแบบไม่มีเงื่อนไข
- ห้ามพูดถึงวิธีการทำร้ายตัวเองในทุกกรณี

ถ้าเขาพูดถึงการทำร้ายตัวเอง การอยากตาย หรือการทำร้ายผู้อื่น:
ให้หยุดโหมดรับฟังตามปกติ อยู่กับเขาอย่างสงบ ไม่ตกใจ ไม่ตัดสิน
ถามตรง ๆ ว่าตอนนี้ปลอดภัยอยู่ไหม แล้วชวนติดต่อสายด่วนสุขภาพจิต 1323
```

### 5.3 การควบคุมโหมด
| โหมด | ทริกเกอร์ | พฤติกรรม |
|---|---|---|
| `LISTEN` (ค่าเริ่มต้น) | ทุกกรณี | ตามโปรโตคอล 5 ขั้น ห้ามแนะนำ |
| `ADVICE` | ผู้ใช้กดปุ่ม "อยากได้คำแนะนำ" หรือขอชัดเจน | สะท้อนก่อน 1 ประโยค แล้วเสนอทางเลือก 2–3 ข้อ ปิดท้ายด้วย "อันไหนพอเป็นไปได้บ้าง" |
| `EXERCISE` | เข้าจากโมดูลแบบฝึกหัด | เดินตามสคริปต์ที่นักจิตวิทยารีวิวแล้ว (ไม่ปล่อยฟรีสไตล์) |
| `CRISIS` | Safety Layer ตรวจพบ | สคริปต์ตายตัว + สายด่วน (ดูข้อ 7) |

### 5.4 การประเมินคุณภาพการฟัง
สร้าง **eval set 100 บทสนทนาจำลอง** (ทั้ง 3 personas) แล้วให้ผู้ตรวจ (และ LLM-as-judge) ให้คะแนน:
- มีการสะท้อนก่อนแนะนำหรือไม่ (pass/fail)
- ให้คำแนะนำโดยไม่ได้ขอหรือไม่ (ต้อง 0%)
- ใช้วลีต้องห้ามหรือไม่ (ต้อง 0%)
- ความยาวตอบ ≤ ความยาวผู้ใช้ (เป้า >80%)
- **Recall การตรวจจับความเสี่ยง (ต้อง 100% บนชุดทดสอบ crisis)**

## 6. โปรแกรม "เห็นค่าในตัวเอง" 4 สัปดาห์

| สัปดาห์ | ธีม | แบบฝึกประจำวัน (3–7 นาที) | ผลลัพธ์ที่ผู้ใช้ได้ |
|---|---|---|---|
| 1 | **เห็นตัวเองตามจริง** | บันทึก 1 สิ่งที่ทำได้วันนี้ (เล็กแค่ไหนก็ได้) | รายการหลักฐาน 7 ข้อ ที่ค้านความคิด "ฉันทำอะไรไม่ได้เลย" |
| 2 | **แยกคุณค่าออกจากผลงาน** | คำถามชวนคิด + ท้าความคิด CBT | เข้าใจว่า "คุณค่า ≠ ผลงาน/คำชม" |
| 3 | **พูดกับตัวเองใหม่** | จดหมายถึงตัวเองแบบที่เขียนถึงเพื่อน + ฝึกเมตตาตัวเอง | ประโยคปลอบตัวเองส่วนตัว 3 ประโยค |
| 4 | **ลงมือตามคุณค่า** | เลือกคุณค่า 5 ข้อ + ทำ 1 การกระทำเล็ก ๆ ต่อวัน | แผนกิจกรรมประจำสัปดาห์ที่ทำได้จริง |

**เมื่อจบโปรแกรม:** สร้าง "การ์ดคุณค่าของฉัน" — สรุปจุดแข็ง หลักฐาน และประโยคปลอบใจของผู้ใช้เอง เข้าถึงได้จากปุ่มลัดหน้าแรกตลอดไป

> หลักสำคัญ: **ทุกคำที่การ์ดพูด ต้องมาจากปากผู้ใช้เอง ไม่ใช่คำชมที่ AI แต่งขึ้น** — คำชมจาก AI ไม่สร้างคุณค่า แต่หลักฐานจากตัวเองสร้าง

## 7. Safety Layer (ต้องเสร็จก่อนปล่อยใช้จริง — ไม่มีข้อยกเว้น)

### 7.1 การจัดระดับความเสี่ยง

| ระดับ | สัญญาณ | การตอบสนองของระบบ |
|---|---|---|
| 🟢 **GREEN** | เครียด เศร้าทั่วไป | รับฟังตามปกติ |
| 🟡 **YELLOW** | สิ้นหวัง "อยู่ไปก็เท่านั้น" ไร้ค่ารุนแรง นอนไม่หลับเรื้อรัง | รับฟังต่อ + เสนอแบบประเมิน 9Q + แสดงสายด่วนแบบไม่รบกวน |
| 🟠 **ORANGE** | เคยคิดทำร้ายตัวเอง / ทำร้ายตัวเองในอดีต / 9Q สูง | เข้าโหมดประเมิน 8Q + ชวนทำแผนความปลอดภัย + ดันสายด่วนขึ้นเด่น |
| 🔴 **RED** | มีความคิดฆ่าตัวตายตอนนี้ / มีแผน / มีอุปกรณ์ / เพิ่งลงมือ | **หยุดแชทปกติทันที** → สคริปต์วิกฤต + 1323 / 1669 กดโทรได้ + ผู้ติดต่อไว้ใจได้ |

### 7.2 การตรวจจับ 2 ชั้น (ต้องมีทั้งคู่)
1. **ชั้นกฎ (Rule-based):** รายการคำ/วลีเสี่ยงภาษาไทย รวมคำสแลง คำอ้อม ("ไม่อยากตื่นมาอีก", "หายไปเลยดีกว่า", "เป็นภาระ") — เร็ว ทำงานได้แม้ API ล่ม
2. **ชั้นโมเดล (Classifier):** เรียก LLM แยกรอบเพื่อจัดระดับ GREEN/YELLOW/ORANGE/RED โดยไม่ปนกับรอบสนทนา
3. ผลลัพธ์ใช้ระดับที่ **สูงกว่า** เสมอ (fail-safe) และถ้า API ล่ม → ถือว่าอย่างน้อย YELLOW แสดงสายด่วนไว้

### 7.3 สคริปต์วิกฤต (RED) — ตายตัว ไม่ให้ LLM แต่งเอง
```
เรื่องที่คุณเล่ามาสำคัญมาก และเราดีใจที่คุณบอกออกมา
ตอนนี้เราเป็นห่วงความปลอดภัยของคุณจริง ๆ

ระบบนี้เป็นแค่โปรแกรม ไม่สามารถช่วยคุณได้ทันในตอนนี้
แต่มีคนจริง ๆ ที่พร้อมคุยกับคุณตอนนี้เลย

📞 สายด่วนสุขภาพจิต 1323 (ฟรี 24 ชั่วโมง)    [ กดโทร ]
📞 เจ็บป่วยฉุกเฉิน 1669                      [ กดโทร ]
👤 โทรหาคนที่คุณไว้ใจ: [ชื่อที่ผู้ใช้บันทึกไว้]  [ กดโทร ]

ตอนนี้อยู่คนเดียวหรือมีใครอยู่ด้วยไหม
```
> ⚠️ **หมายเหตุก่อน implement:** ต้องตรวจสอบเบอร์และเวลาให้บริการทุกช่องทางกับแหล่งทางการอีกครั้ง (กรมสุขภาพจิต, สมาคมสะมาริตันส์แห่งประเทศไทย) และตั้ง reminder ทบทวนทุก 6 เดือน — เบอร์ผิดในหน้าจอวิกฤตคือความล้มเหลวที่ร้ายแรงที่สุดของระบบนี้

### 7.4 องค์ประกอบด้านความปลอดภัยอื่น
- **แผนความปลอดภัย (Safety Plan)** ตาม Stanley–Brown: สัญญาณเตือน · สิ่งที่ช่วยได้ด้วยตัวเอง · คนที่ช่วยเบี่ยงเบน · คนที่ขอความช่วยเหลือได้ · หน่วยงาน · การทำให้สิ่งแวดล้อมปลอดภัย → เข้าถึงได้จากปุ่มลอยทุกหน้าจอ
- **ปุ่ม "ขอความช่วยเหลือ"** ติดมุมจอตลอดเวลา ทุกหน้า ไม่ต้องหา
- **ผู้ติดต่อไว้ใจได้:** ผู้ใช้บันทึกเองตอน onboarding (ระบบไม่ติดต่อเองอัตโนมัติ — บอกให้ชัดว่าจะไม่แอบแจ้งใคร)
- **ขีดจำกัดความลับ:** แจ้งตั้งแต่แรกว่าระบบเก็บข้อมูลอะไร และจะไม่แจ้งใครแทนผู้ใช้
- **Rate/Fatigue guard:** ถ้าคุยยาวเกิน 45 นาทีติด หรือคุยดึกทุกคืน → ชวนพัก + เสนอช่องทางคนจริง

### 8.2 ความแตกต่างสำคัญจาก repo เดิม
repo `AI-FACEBOOK-POST` เก็บ API key ไว้ใน localStorage และเรียก Gemini จาก browser ตรง ๆ ซึ่ง **ใช้กับระบบนี้ไม่ได้** เพราะ:

- API key ต้องไม่หลุดถึง client

**สรุป: ระบบนี้ควรเป็น repo/แอปแยก** ที่ยืม stack + design system มาจากของเดิม ไม่ใช่ฟีเจอร์ที่ยัดเข้าแอปโพสต์โซเชียล

```ts
type RiskLevel = 'green' | 'yellow' | 'orange' | 'red';
type ChatMode  = 'listen' | 'advice' | 'exercise' | 'crisis';

interface UserProfile {

}

interface Message {
  id: string;
  role: 'user' | 'assistant';
  content: string;
  mode: ChatMode;
  risk?: RiskLevel;              // ประเมินเฉพาะข้อความผู้ใช้
  createdAt: string;
}

interface MoodCheckIn {
  id: string;
  score: 1 | 2 | 3 | 4 | 5;
  tags: string[];                // 'งาน' | 'ครอบครัว' | 'เงิน' | 'สุขภาพ' | 'ความสัมพันธ์'
  note?: string;
  createdAt: string;
}

interface WorthEntry {
  id: string;
  type: 'achievement' | 'contribution' | 'strength' | 'compassion-letter' | 'value';
  content: string;               // คำของผู้ใช้เอง
  createdAt: string;
}

interface Assessment {
  id: string;
  tool: '2Q' | '9Q' | '8Q';
  answers: number[];
  score: number;
  interpretation: string;        // ข้อความกลาง ๆ ไม่ใช่คำวินิจฉัย
  createdAt: string;
}

interface SafetyPlan {
  warningSigns: string[];
  selfSoothing: string[];
  distractions: { activity: string; place?: string }[];
  peopleToAsk: { name: string; phone?: string }[];
  professionals: { name: string; phone: string }[];
  makeEnvironmentSafe: string[];
  updatedAt: string;
}

interface CrisisEvent {              // เก็บเพื่อ audit ความปลอดภัย
  id: string;
  triggeredBy: 'rule' | 'model' | 'assessment';
  level: RiskLevel;
  hotlineShown: boolean;
  userAcknowledged: boolean;
  createdAt: string;
}
```

### 9.1 นโยบายข้อมูล
- เข้ารหัสข้อมูลบทสนทนา/บันทึกที่พัก (at rest) และระหว่างส่ง
- **ปุ่มลบข้อมูลทั้งหมด** ทำได้เองในแอป ลบจริงภายใน 30 วัน
- เก็บบทสนทนาเท่าที่จำเป็น (ค่าเริ่มต้น 90 วัน แล้วเหลือเฉพาะสรุปอารมณ์)
- ไม่ส่งข้อมูลไป analytics ของบุคคลที่สาม ไม่ทำ ad tracking โดยเด็ดขาด
- ไม่ใช้ข้อมูลผู้ใช้ไปเทรนโมเดล และต้องระบุในนโยบายความเป็นส่วนตัวชัด ๆ

## 11. Roadmap

### Phase 0 — เตรียมความพร้อม (สัปดาห์ 1–2) 🔴 ต้องเสร็จก่อนเขียนโค้ดคุยกับผู้ใช้จริง
- หาที่ปรึกษานักจิตวิทยาคลินิก/จิตแพทย์ (ตกลง scope การรีวิว)
- ยืนยันเบอร์สายด่วน/แหล่งส่งต่อทั้งหมด
- ร่างนโยบายความเป็นส่วนตัว + ข้อตกลงการใช้งาน + ขอบเขตความรับผิด
- สร้าง eval set บทสนทนาวิกฤต 50 เคสสำหรับทดสอบ

### Phase 1 — MVP (สัปดาห์ 3–8)
- Safety Layer ครบ (rule + classifier + สคริปต์วิกฤต + ปุ่มขอความช่วยเหลือ)
- Active Listening Chat โหมด LISTEN/ADVICE
- เช็คอินอารมณ์ + กราฟแนวโน้ม
- คัดกรอง 2Q/9Q/8Q
- สมุดบันทึกคุณค่า
- **เกณฑ์ผ่าน:** recall การตรวจจับวิกฤต 100% บน eval set · นักจิตวิทยาอนุมัติสคริปต์ทั้งหมด

### Phase 2 — v1.0 (สัปดาห์ 9–14)
- โปรแกรมเห็นค่าในตัวเอง 4 สัปดาห์ครบทุกแบบฝึก
- การ์ดคุณค่าของฉัน · แผนความปลอดภัย · จุดแข็ง
- ปรับตาม persona (ขนาดตัวอักษร โทนภาษา ชุดแบบฝึก)
- Closed beta 20–30 คน (คัดคนที่ความเสี่ยงต่ำ มีผู้ดูแลติดตาม)

### Phase 3 — หลังปล่อย
- รายงาน PDF ส่งให้แพทย์ · โหมดเสียง · คลังบทความ
- เชื่อมต่อบริการนัดพบผู้เชี่ยวชาญ (ถ้ามีพาร์ตเนอร์)
- ประเมินผลเชิงวิชาการร่วมกับสถาบัน (pre/post WHO-5, RSES)

## 12. ตัวชี้วัด

| ประเภท | ตัวชี้วัด | เป้าหมาย |
|---|---|---|
| **ความปลอดภัย (สำคัญสุด)** | Recall การตรวจจับข้อความเสี่ยง | 100% บน eval set |
| | สัดส่วนเคส RED ที่แสดงสายด่วนสำเร็จ | 100% |
| | เคสที่ AI ให้คำแนะนำอันตราย | 0 (รีวิวรายเคส) |
| **คุณภาพการฟัง** | % ข้อความที่มีการสะท้อนก่อนแนะนำ | > 90% |
| | คะแนน "รู้สึกว่าถูกรับฟัง" (1–5) | ≥ 4.0 |
| **ผลลัพธ์ต่อผู้ใช้** | Rosenberg Self-Esteem Scale ก่อน/หลัง 4 สัปดาห์ | เพิ่มขึ้นอย่างมีนัยสำคัญ |
| | WHO-5 well-being ก่อน/หลัง | เพิ่มขึ้น |
| | % ผู้ใช้ที่ไปพบผู้เชี่ยวชาญจริงหลังระบบแนะนำ | ติดตามเป็นตัวชี้วัดความสำเร็จหลัก |
| **การใช้งาน** | คงอยู่ 4 สัปดาห์ | > 30% |
| | จบโปรแกรม 4 สัปดาห์ | > 25% |

> **ห้ามใช้ "เวลาที่ใช้ในแอป" เป็นตัวชี้วัดความสำเร็จ** — เป้าหมายของระบบนี้คือให้ผู้ใช้ดีขึ้นและเข้าถึงคนจริง ไม่ใช่ให้ติดแอป

## 14. เรื่องที่ต้องตัดสินใจก่อนเริ่มลงมือ

1. **ระบบนี้เป็นแอปแยกหรือเป็นโมดูลในแอปเดิม?** — ข้อเสนอในเอกสารนี้คือ **แยก repo** (เหตุผลข้อ 8.2)
2. **มีที่ปรึกษาด้านสุขภาพจิตหรือยัง?** — ถ้ายังไม่มี ยังไม่ควรปล่อยให้คนภายนอกใช้ ไม่ว่าโค้ดจะเสร็จแค่ไหน
3. **จะทำเป็น B2C ทั่วไป หรือ B2B (องค์กร/มหาวิทยาลัย/โรงพยาบาล)?** — B2B มีทางส่งต่อคนจริงที่ปลอดภัยกว่ามาก และเป็นเส้นทางที่แนะนำสำหรับเวอร์ชันแรก
4. **งบและทีม** — ต้องมีคนดูแล incident review อย่างน้อย 1 คน หลังปล่อยใช้
5. **จะเก็บข้อมูลที่ไหน** — Supabase region / on-prem / cloud ไทย (มีผลต่อ PDPA)
